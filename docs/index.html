Dokumentasi Kitab Link

Link-in-bio self-hosted — Next.js + SQLite, 1 file database, deploy pakai Docker.

Instalasi Mudah

Cara paling gampang — 1 command, script yang urus semuanya.

Jalankan script instalasi 
curl -fsSL https://raw.githubusercontent.com/Kurohiko-id/Kitab-Link-Self-Hosted/main/install.sh | bash
  • Install Docker otomatis kalau belum ada di server.
  • Install & configure Caddy otomatis (atau nyambung ke Caddy yang udah jalan kalau server ini udah dipakai app/domain lain) — HTTPS, reverse proxy, semua udah diatur.
  • Tinggal jawab beberapa pertanyaan singkat (bahasa, folder install, domain, nama container), sisanya diurus script.
Kalau sebelumnya Docker belum ke-install di server, sesi SSH bakal ke-logout otomatis setelah Docker selesai diinstall. Login ulang SSH, lalu jalankan command curl -fsSL https://raw.githubusercontent.com/Kurohiko-id/Kitab-Link-Self-Hosted/main/install.sh | bash sekali lagi buat lanjutin instalasi.
Butuh kontrol penuh? Ikuti Manual Installation

Quick Start

Cara manual pakai Docker Compose — kalau lebih suka atur sendiri.

Butuh Docker + Compose. Cocok kalau server-nya cuma buat app ini doang.

1. Download compose file 
curl -O https://raw.githubusercontent.com/Kurohiko-id/Kitab-Link-Self-Hosted/main/docker-compose.yml
2. Jalankan 
docker compose up -d

Migration jalan otomatis. Buka http://IP-SERVER:3000 — diarahin ke setup kalau belum ada akun.

Setup Admin

/setup minta username, password, dan token. Token SENGAJA cuma ada di log (biar orang lain gak bisa daftar duluan):

Ambil token setup 
docker logs kitab-link | grep "Setup token"

Token sekali pakai, invalid otomatis kalau container restart sebelum setup selesai.

Reverse Proxy

Banyak app 1 server? Pakai Caddy/Nginx di depan buat routing per-domain + HTTPS.

Pakai Cloudflare? Set SSL mode "Full (strict)" — mode "Flexible" bikin redirect loop / gagal login.

Domain Kustom per Page

Tiap page (mis. /main, /kerja) bisa dipasangin domain sendiri-sendiri (mis. namamu.com) — independen dari domain utama tempat Kitab Link kamu jalan.

  1. Arahin domain custom-nya (DNS A record) ke IP server ini, lewat penyedia DNS kamu (Cloudflare, dll).
  2. Tambahin block baru di Caddyfile, isinya nunjuk ke container yang SAMA kayak domain utama (bukan container baru) — lalu reload Caddy-nya.
  3. Masukin domain yang sama persis di dashboard → tab Domain & Access, pilih page mana yang mau ditampilin lewat domain itu.
Contoh block Caddyfile 
namadomainmu.com {
    reverse_proxy nama_container_kitablink:3000
}
Reload Caddy (kalau jalan via Docker Compose) 
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
Isian domain di dashboard doang BELUM CUKUP — itu cuma bikin app-nya tau "kalau ada request dari domain ini, tampilin page X". DNS dan Caddy tetep wajib diatur manual kayak di atas.

Badge "Traffic terdeteksi" di dashboard cuma nyala begitu ada request beneran yang masuk lewat domain itu — bukan verifikasi DNS asli. Halaman admin (/dashboard, /login, /setup) selalu diblokir kalau diakses lewat domain custom, demi keamanan.

Automasi

  • YouTube Live — grup/link auto muncul pas live, ilang pas kelar.
  • Live Badge — badge "sedang live", independen dari fitur di atas.
  • Jadwal Mingguan — link muncul/hilang di hari & jam tertentu.
  • RSS/Atom — konten baru dari feed otomatis jadi link.

Keamanan

Argon2id — hashing password, bukan bcrypt/MD5.
2FA TOTP + backup codes.
Password per page — beda dari password akun.
Lupa password — jalankan docker logs <container_name> buat ambil token/link reset, gak lewat email.

Backup & Restore

Export/import JSON, bisa pilih terpisah: Tema, Profil & SEO, Link & Grup. Import ada konfirmasi (destruktif) + validasi versi.

Update Versi

1. Tarik image terbaru 
docker compose pull
2. Restart container 
docker compose up -d

Migration jalan otomatis lagi. Dashboard notif kalau ada rilis lebih baru.
